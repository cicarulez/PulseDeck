# PulseDeck 0.10.0 — development snapshot

Updated 4 October 2026. This records the current source version; no tag, downloadable
0.10.0 archive or published release is implied. Existing downloaded/installed builds
can be older. Review [publishing](../publishing.md) before preparing a release.

## Changes

- Optional Music layout with three hardware widgets above a real 24-band spectrum,
  captured from Spotify's process tree on Windows and analysed locally in memory.
- Passive Aura colors distributed across spectrum bars, wordmark and active lyrics.
  Sensor graphs retain a uniform color for readability.
- Manual display brightness (0–100%). With a saved manual value, Aura Scuro (OFF)
  darkens the panel; resumed or unavailable Aura restores the configured brightness.
- Separate acquisition, animated rendering and USB delivery. Browser previews
  use frame revisions and recover from delayed image loads without a page refresh.
- Monotonic song-progress interpolation with bounded extrapolation.
- Standalone refresh, audio and internal-playback research tools, with protocol tests.
- Dedicated GitHub Pages homepage and generated HTML documentation, including
  navigation, page contents, mobile layouts and checked local links.

## Verified results and limits

The browser preview ran near 10 fps and remained fluid in the user's follow-up.
A five-minute independent full-frame USB probe delivered 1,300 frames at 4.33 fps,
without transport errors or user-reported artifacts. Raising process priority did
not materially improve delivery. This is not a claim of 8 fps on the panel.

An original H.264 test clip was uploaded and played internally, then deleted;
PulseDeck and the configured brightness were restored. The user found it smoother
than the spectrum but less fluid than the vendor's AMD animation. Encoded 24 fps
is not a measured display rate. Live video overlays were rejected and remain
experimental; normal dashboards continue using the verified bitmap transport.

Aura OFF dimming and brightness restoration were checked on the development setup.
Automated tests cover unavailable Aura and state transitions; this does not replace
broader physical reboot, service-loss, sleep/wake and other-device validation.

See [validation](../validation.md), [playback research](../turzx_internal_playback_research.md)
and [roadmap](../roadmap.md) for evidence and remaining work. No firmware was flashed.
